# 6. Оптимизация производительности

Как сделать, чтобы игра работала плавно даже на слабых телефонах — а большинство игроков Roblox играют именно с мобильных устройств.

## 🎯 Главный принцип

> Считайте, что **бюджет кадра — ~16 мс** (60 FPS), а на телефонах — ещё меньше. Всё, что вы делаете каждый кадр, должно быть дешёвым.

## 🧱 Оптимизация мира и физики

- **Anchored везде, где можно.** Каждая незакреплённая деталь — нагрузка на физический движок. Двигайте всё, что стоит на месте.
- **Меньше деталей — лучше.** Объединяйте статику: используйте `UnionOperation`/`MeshPart` вместо сотен мелких Part.
- **CanCollide = false** для декоративных объектов (трава, флаги, мелкие камни).
- **CanQuery / CanTouch = false** для объектов, с которыми ничего не взаимодействует.
- **StreamingEnabled** (включён по умолчанию) — выгружает дальние части мира. Проверяйте, что логика корректно работает со стримингом: объекты могут появляться и исчезать.
- Спавните врагов/предметы **по мере необходимости** и уничтожайте то, что больше не нужно.

## 💻 Оптимизация кода

- **Не используйте `while true do` без паузы.** Всегда `task.wait()` внутри.
- **RenderStepped** (только клиент) — для кода, который реально нужен каждый кадр. Для логики раз в секунду хватит `task.wait(1)`.
- **Отключайте ненужные соединения:** `connection:Disconnect()`. Утечка событий — частая причина лагов.
- **Кэшируйте сервисы и данные:** `local Players = game:GetService("Players")` один раз, а не в каждом вызове функции.
- **`FindFirstChild` вместо индексации** `workspace.Part` — не выбросит ошибку, если объекта ещё нет.
- **Мусор в циклах:** не создавайте таблицы/векторы каждый кадр без необходимости.
- `ipairs`/обобщённая итерация быстрее `pairs` для массивов.

```lua
-- ❌ плохо: пересоздаём соединение и ищем объект каждый кадр
RunService.Heartbeat:Connect(function()
	local part = workspace:FindFirstChild("Spin")
	part.CFrame = part.CFrame * CFrame.Angles(0, math.rad(2), 0)
end)

-- ✅ хорошо: ищем один раз, вращаем через RenderStepped с дельтой
local part = workspace:WaitForChild("Spin")
RunService.RenderStepped:Connect(function(dt)
	part.CFrame *= CFrame.Angles(0, math.rad(90) * dt, 0)
end)
```

## 🖼️ Графика

- **Текстуры:** степени двойки (512×512, 1024×1024), сжимайте исходники перед загрузкой.
- **Освещение:** `Future` — красивое, но дорогое; для мобильных игр часто хватает `ShadowMap`.
- **Меньше источников света** (PointLight/SpotLight) — каждый свет считается отдельно.
- **Пост-обработка** (Bloom, ColorCorrection) — в меру, особенно на мобильных.
- **PartOperation/Union:** много полигонов = тормоза. Упрощайте меши в Blender перед импортом.
- **LOD:** для MeshPart настройте `RenderFidelity` — дальние модели будут упрощаться.

## 📡 Сеть

- **Не спамьте RemoteEvent.** Отправляйте реже, пачками; не шлите данные, которые клиент и так знает.
- **Сервер — авторитет.** Клиент отправляет намерение («хочу прыгнуть»), сервер проверяет и применяет.
- Тяжёлые вычисления (поиск пути, генерация) делайте **в отдельные кадры** или через `task.defer`/корутины.

## 📊 Инструменты

| Инструмент | Что показывает |
|------------|----------------|
| **MicroProfiler** (`Ctrl+F6`) | детальный профиль времени кадра по подсистемам |
| **Developer Console** (`F9`) | ошибки, память, сеть, скрипты |
| **Script Performance** (в Dev Console) | сколько времени ест каждый скрипт |
| **Stats** (`Ctrl+F7` / `stats()`) | FPS, пинг, нагрузка |

## ✅ Чек-лист перед релизом

- [ ] Все статические детали Anchored
- [ ] Нет `while true do` без `task.wait`
- [ ] События отключаются, когда объект умирает
- [ ] Проверено на телефоне (минимальный FPS — по нему)
- [ ] MicroProfiler не показывает «красных» пиков
- [ ] Нет утечек памяти при перезаходе игроков

# 7. Безопасность

Как защитить аккаунт, деньги и нервы — и игрокам, и разработчикам, и родителям.

## 🔐 Защита аккаунта

1. **Уникальный сложный пароль.** Не используйте пароль от почты или других сайтов. Менеджер паролей — ваш друг.
2. **Двухфакторная аутентификация (2FA).** Настройки → Security → включите подтверждение по почте или через приложение-аутентификатор. Без 2FA аккаунт могут угнать за минуты.
3. **Проверенная почта.** Почта — ключ восстановления. Защитите её так же, как аккаунт Roblox.
4. **Никогда не вводите пароль** на сторонних сайтах, «в играх» или по просьбе «администрации». Администрация никогда не просит пароль.
5. **Не делитесь аккаунтом** с друзьями — это и нарушение правил, и прямой путь к потере аккаунта.

## 🚨 Скам: как обманывают в Roblox

| Схема | Как выглядит | Правда |
|-------|--------------|--------|
| «Бесплатные Robux» | Сайты-генераторы, «введи логин — получишь R$» | Генераторов Robux **не существует**. Это кража пароля |
| «Хаки/читы» | Программы для взлома игр | Содержат вирусы, ведут к бану аккаунта |
| Фишинговые ссылки | «Посмотри мой новый трейлер → ссылка» | Ссылка ведёт на поддельный сайт входа |
| «Обмен с предоплатой» | «Сначала отдай вещь, потом я заплачу» | Классическое мошенничество в трейдах |
| Фейковая поддержка | «Ваш аккаунт заблокирован, подтвердите пароль» | Поддержка не пишет в личку и не просит пароль |

**Правило одно:** если предлагают что-то бесплатно и слишком хорошо — это обман.

## 👨‍👩‍👧 Для родителей

- **Родительский контроль:** в настройках аккаунта ребёнка можно ограничить чат, круг общения и доступные игры по возрастному рейтингу.
- **PIN-код настроек:** включите родительский PIN, чтобы ребёнок не смог отключить ограничения.
- **Возрастные рейтинги:** у игр Roblox есть метки (All Ages, 9+, 13+, 17+) — обращайте на них внимание.
- **Разговор важнее запретов:** объясните ребёнку, что нельзя сообщать настоящие имя, адрес, школу и пароль, а обо всём подозрительном нужно рассказывать взрослым.
- **Траты:** покупки Robux привяжите к способу оплаты, о котором вы знаете; обсуждайте траты заранее.

## 🛡️ Безопасность для разработчиков

- **Сервер — единственный источник правды.** Все важные проверки (валюта, урон, покупки) — на сервере. Эксплойтеры могут выполнять ЛЮБОЙ код на клиенте.
- **Валидируйте входные данные** из RemoteEvent/RemoteFunction: тип, диапазон значений, права игрока, анти-спам (rate limiting).
- **RemoteFunction — с осторожностью:** клиент может не ответить и «повесить» сервер через `:InvokeClient()`. Избегайте этого паттерна.
- **Права доступа к DataStore/платежам** — только серверные скрипты.
- **Не храните секреты в клиентских скриптах** — их легко прочитать.

```lua
-- пример валидации на сервере
buyEvent.OnServerEvent:Connect(function(player, itemId)
	-- 1. тип данных
	if typeof(itemId) ~= "string" then return end
	-- 2. такой предмет вообще существует?
	if not ITEMS[itemId] then return end
	-- 3. анти-спам
	if os.clock() - (lastBuy[player] or 0) < 0.5 then return end
	lastBuy[player] = os.clock()
	-- 4. только теперь — логика покупки
end)
```
